SecurityConfig

br.edu.ifsp.associacaogaia.config
Configuração central de segurança da aplicação (Spring Security). <p> Define a política de autenticação/autorização da API: a aplicação não usa sessão HTTP (é stateless, pois a autenticação é feita via token JWT em cada requisição), define quais rotas são públicas e quais exigem autenticação ou um papel (role) específico, e registra o filtro customizado SecurityFilter responsável por validar o token JWT antes do filtro padrão de autenticação por usuário/senha do Spring Security. <p> A anotação EnableMethodSecurity habilita o uso de anotações como @PreAuthorize diretamente nos métodos dos controllers, o que é usado, por exemplo, para restringir a busca de um usuário por id/e-mail ao próprio usuário autenticado ou a um administrador.

Método
public SecurityFilterChain securityFilterChain(HttpSecurity http)
Constrói e configura a cadeia de filtros de segurança HTTP da aplicação. <p> Regras aplicadas: <ul> <li>CSRF desabilitado (API stateless consumida via token, sem uso de cookies de sessão);</li> <li>Política de sessão definida como STATELESS (nenhum estado de sessão é mantido no servidor entre requisições);</li> <li>POST /api/usuarios/login liberado para qualquer requisição (é o endpoint de autenticação);</li> <li>POST /api/usuarios liberado para qualquer requisição (é o endpoint de cadastro de novo usuário/visitante);</li> <li>GET /api/usuarios restrito a usuários com papel ADMINISTRADOR (listagem completa de usuários);</li> <li>Qualquer outra requisição exige autenticação (o controle mais fino de quem pode acessar o quê, como "o próprio usuário ou um administrador", é feito via @PreAuthorize nos métodos do controller);</li> <li>O filtro securityFilter é adicionado antes do filtro padrão UsernamePasswordAuthenticationFilter, garantindo que o token JWT seja validado e o usuário autenticado no contexto de segurança antes de qualquer outra checagem.</li> </ul>
Parâmetros:
  • http — objeto de configuração fornecido pelo Spring Security, usado para declarar as regras de autorização e filtros.
Retorno: a SecurityFilterChain construída com as regras acima.
Exceções:
  • Exception — se ocorrer algum erro ao construir a cadeia de filtros (propagado pela API do Spring Security).
